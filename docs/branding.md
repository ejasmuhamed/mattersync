## App identity and artwork

- Brand name, palette, publisher, and the app-only translation IDs: `assets/base/branding/brand.json`.
- Original editable mark: `assets/base/branding/mark.svg`. It uses two conversation bubbles and a voice waveform; it does not adapt the upstream dial logo.
- Native iOS icons, Android launcher/adaptive/monochrome icons, notification icons, light/dark launch images, in-app artwork, and store graphics are generated by `python3 scripts/generate-brand-assets.py` (Python 3 with Pillow).
- The iOS marketing icon is 1024×1024 RGB, with no alpha channel. The Play listing icon is 512×512 RGB. Android foreground artwork stays within the adaptive icon safe area.
- App-specific strings are renamed while server compatibility references remain. Runtime translations apply the app name only to the allowlisted message IDs; other locale JSON files remain unchanged.
- The About screen identifies the independent publisher and retains upstream copyright notices. Server edition and server policy links describe the connected server, not a Mattersync enterprise product or Bytsolv's own policies.

Internal React Native module names, source directories, native package namespaces, URL protocols, server APIs, upstream dependency coordinates, compatibility emoji, and license/NOTICE attribution are not app marketing names. They are intentionally not renamed as part of this visual rebrand. Device signing and provisioning configuration may be managed separately.

## App identifiers

The installed iOS and Android app ID is `com.bytsolv.mattersync`. The iOS extensions use `com.bytsolv.mattersync.MattermostShare` and `com.bytsolv.mattersync.NotificationService`. All three iOS targets share `group.com.bytsolv.mattersync`; the main app uses `iCloud.com.bytsolv.mattersync` and its own keychain group.

Fastlane build environments use these same IDs. Android keeps its internal Java/Kotlin namespace separate from the application ID; `ANDROID_NAMESPACE` controls that source namespace if an explicit migration is needed.

Register the new iOS IDs, App Group and iCloud container with the signing team and regenerate provisioning profiles before signing. For push delivery, use `com.bytsolv.mattersync` as the APNs topic. Register the Android app with that package name in your own Firebase project and replace `android/app/google-services.json` with the downloaded configuration. The upstream Firebase clients do not register this new package ID, and changing their package strings does not create a Firebase app.

Existing installed builds and signed artifacts retain their previous IDs until rebuilt and installed; this change does not migrate their local app data. App Store/Play records and push-service configuration also require the new identifiers.

## Store submission items still required

1. Resolve the existing MatterSync name uses described above. Review [Mattermost's trademark policy](https://mattermost.com/trademark-standards-of-use/), [Apple's copycat/impersonation guidance](https://developer.apple.com/help/app-review/guideline-reference/4-1-prevent-copycat-rejection), and [Google Play's impersonation policy](https://support.google.com/googleplay/android-developer/answer/9888374).
2. Review and publish the app-specific [privacy notice draft](privacy.md) at a stable public URL. Set `fastlane/metadata/en-US/privacy_url.txt` and `AppPrivacyPolicyURL` in `assets/base/config.json` to that actual published URL. Both are deliberately empty rather than pointing to the upstream company's unrelated policy. The app privacy link appears after the URL is configured; server policy links are separately labeled. Complete the App Store privacy and Google Play Data safety declarations for the actual release configuration.
3. Set the publisher-owned store bundle/application identifiers and signing credentials. The example identifier is illustrative and is not proof of ownership. Release pipelines must not use upstream Mattermost-owned identifiers, store records, accounts, or notification infrastructure.
4. Capture fresh screenshots from this branded app, including its voice-message UI. Do not use screenshots of the official client as Mattersync screenshots. Store artwork does not substitute for screenshots or runtime testing.
5. Rebuild and verify the app name, icons, launch screen, About page, share target, call notification, and permission wording on iOS and Android. Existing installed builds do not acquire a new native icon merely from a JavaScript reload.
6. Include `LICENSE.txt`, `NOTICE.txt`, and the applicable dependency notices in the distributed package. Preserve the original copyright notices; the app includes modified upstream software.

No store submission, signing-identity change, repository publication, or trademark registration is performed by the branding generator.
